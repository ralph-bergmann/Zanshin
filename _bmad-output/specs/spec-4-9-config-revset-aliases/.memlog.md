- (direction by user) Ralph (2026-08-23): create a follow-up story so config-driven revset aliases are not forgotten; include jj docs links for later reading. Context: spec-4-8's open question — Zanshin ships builtin aliases only, so users with customized trunk()/immutable_heads()/own aliases see diverging diamond-flags/default view and get parse errors for their aliases.
- (decision) Placement: story 4-9 under the reopened Epic 4, directly after 4-8 (it completes 4-8's CLI-parity goal and resolves its open question). Crate ownership is zanshin-jj, but Epic-4 stories already span crates; re-keying to Epic 9 later is cheap if Ralph prefers. DEPENDS ON 4-8 (the builtin-alias table seam in build_aliases_map, crates/zanshin-jj/src/revset.rs:146, is what 4-9 turns config-fed).
- (capability) CAP-1 config-fed alias resolution: revset parsing in zanshin-jj resolves [revset-aliases] from the jj config stack (builtin defaults < user config files/JJ_CONFIG < repo config, CLI precedence) — overridden builtins (trunk(), immutable_heads()) and user-defined aliases (wip(), mine()) parse exactly as the jj CLI resolves them, everywhere revsets are parsed (graph slice incl. immutable containment, revset resolution, prioritize, short_prefixes); success = alias-override and custom-alias tests produce CLI-equal resolution incl. the immutable flag flip.
- (capability) CAP-2 effective log defaults readable: the config-resolved values of revsets.log, revsets.log-graph-prioritize, revsets.short-prefixes and ui.log-synthetic-elided-nodes are exposed (typed read, per repo handle) so the UI pre-fills what the CLI would actually use instead of hardcoded builtin constants (FR-JJ-17: pre-fill = the CLI-applied default, still user-editable); success = a repo config override of revsets.log is what the read returns.
- (constraint) Precedence and error behavior mirror the jj CLI at the pinned tag (v0.42.0): layer order builtin defaults < user config < repo config (JJ_CONFIG replaces user-file discovery; no --config CLI-arg layer in Zanshin); a malformed config or alias surfaces an error the way the CLI does — never a silent fall-back to builtins. Observable behavior verified against cli/src/config.rs + lib/src/config.rs (StackedConfig/ConfigLayer/ConfigSource) at build time.
- (constraint) Coherency over caching (ADR-0002 spirit): config is re-read per operation — .jj/repo/config.toml and user config can change externally and the op-heads watcher does NOT cover them; two small TOML reads per call are assumed cheap. If measurement at build time forces per-handle caching, the invalidation strategy must be designed and documented, not implied.
- (constraint) ACL + seam: config loading lives entirely in zanshin-jj (sole jj_lib importer); the 4-8 builtin-alias table (build_aliases_map, revset.rs) becomes the default layer that config layers override — one alias-resolution path for ALL parse sites, no second code path. zanshin-mcp gets the behavior for free (consumes zanshin-jj directly). Tests keep pinning JJ_CONFIG/GIT_CONFIG_GLOBAL — which is now also the lever to inject test configs.
- (decision) Non-goals fixed: template aliases / custom log templates (GUI replaces template UX; 4-8's row catalog is the fixed content contract); a general settings surface beyond CAP-2's four values; the --config command-line layer; fileset aliases; writing/editing config from Zanshin; FFI exposure beyond CAP-2 (aliases act inside existing calls, they do not cross the wire).
- (assumption) jj-lib 0.42 exposes what is needed without porting CLI code wholesale: StackedConfig/ConfigLayer/ConfigSource (lib/src/config.rs, verified in the vendored crate) and RevsetAliasesMap injection into RevsetParseContext (already used in revset.rs). The CLI-side file-discovery order (ConfigEnv, cli/src/config.rs @ v0.42.0) is replicated as observable behavior, not linked.
