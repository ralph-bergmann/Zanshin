## Intent

**Problem:** The Immutable commits page names `untracked_remote_bookmarks()` / `untracked_remote_tags()` members by inferring "untracked" from `TopologyRef.synced` ("tracked AND agrees with local"), so a tracked remote ref that moved away from its local target is wrongly listed as untracked (deferred-work I1, Story 11.7 closing run).

**Approach:** Carry jj's remote-ref tracking state over the bridge as a `tracked` flag on `CommitRef` / `TopologyRef` — the jj CLI's `CommitRef.tracked()` template keyword (`cli/src/commit_templater.rs` @ v0.46.0: remote entry → `RemoteRef::is_tracked()`, local entry → false), for bookmarks and tags — and have the page filter on `!tracked`.

## Boundaries & Constraints

**Always:** `tracked` mirrors the CLI keyword exactly (local entry false; remote entry = `remote_ref.is_tracked()`). FlatBuffers field appended at the END of `table TopologyRef` (wire compatibility). Run `cargo make codegen` and commit the generated files. Keep the `git` remote exclusion in `_untrackedRemote` (jj's untracked revsets ignore `git`). Which entries are emitted (the `collect_distinct_refs` rule) stays unchanged.

**Never:** Any other consumer of the flag (non-goal per epics.md 11.21). No change to `synced` semantics or to which refs are emitted. No new bridge verb. No full quality gate (`cargo make test`/`test-full`/`coverage`) in this run.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Tracked, moved | local `unsynced`→c2, `unsynced@origin` tracked →c3 | remote entry on c3: `tracked == true`, `synced == false`; page does NOT name `unsynced@origin` | none |
| Untracked remote | `untracked@origin` untracked →c3 | `tracked == false`; page names `untracked@origin` | none |
| Local entry | any local bookmark/tag | `tracked == false` | none |
| Remote tag | tracked / untracked remote tag | same as bookmarks under `untracked_remote_tags()` | none |
| `git` remote | `x@git` | never named by the untracked terms | none |

## Design Notes

`tracked` rather than an `untracked` flag: it is the CLI's own keyword name and semantics (local entry false), so the bridge passes jj's fact through instead of a page-specific negation; epics.md 11.21 allows either ("an `untracked` flag … or a read of its own"). The page's predicate stays `remote != null && remote != 'git' && kind matches && !tracked`, which is exactly jj's `untracked_remote_*()` (remote refs with state `New`, `git` excluded).
