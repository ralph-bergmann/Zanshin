## Deferred from: code review of 3-2-handle-module-ffi-strings-zanshin-ffi-version (2026-06-15)

- **`build.rs` git-SHA stamp goes stale under git worktrees / shallow clones** [`crates/zanshin-ffi/build.rs:20`] — `cargo:rerun-if-changed=../../.git/logs/HEAD` assumes `.git` is a directory two levels up. In a linked worktree (or submodule) `.git` is a *file* and the reflog lives under the common dir; shallow/fresh clones may lack `.git/logs/HEAD`. In both cases the rerun trigger watches a nonexistent path, so the SHA stamp never refreshes when HEAD moves. The spec Dev Notes consciously chose simplicity ("do not over-engineer ref-walking"; a stale stamp "is fine for a build-stamp"). Low-impact (cosmetic build-stamp in WIP). Contrived; low impact for a WIP build-stamp.

## Deferred from: architecture discussion — logging sink (2026-06-18, Winston)

Its strongest future payoff is `zanshin-mcp`: OSLog is a clean non-stdio sink that satisfies AR-P-5-MCP natively. Revisit at release as an *added* layer (keep the file as source of truth), verify the crate against the pinned Rust toolchain + current macOS, and record an ADR (touches AR-P-5). Crate: `tracing-oslog` (@Absolucy, permissive zlib/MIT-style license).
