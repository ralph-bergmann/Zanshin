# Zanshin — project notes

- Primary client: **`JJ Desktop Client Floating.html`** — the reference for all design work and the design system. The other versions (docked client, studies) stay for reference; don't delete them.
- `Search Study.html` keeps every search-field variant for experiments (its own files: `search-study.jsx/.css`, `revset-config-search.jsx`, `search-one.jsx` (model "One menu"), `app-float-search.jsx`, separate storage keys). The client ships the chosen variant in `graph-search.jsx` + `search.css`.
- `Inspector Study.html` is the approved mock-up of the inspector rebuild (sync #25, Stories 10.35, 10.36, 10.38, 10.39; own files `inspector-study.jsx/.css`, storage `zanshin.inspStudy.*`). The floating client's `inspector.jsx` still shows the old inspector.
- `Whitespace Study.html` (2026-11-15, own files `whitespace-study.jsx/.css`, styles from `inspector-study.css`): the inspector diff while whitespace is ignored, on Ralph's `text_field.dart` case — rows exactly as `jj diff -w`, re-indented lines always marked, far ones collapsed to a gap row "N more lines with only whitespace changes · Show" (open: "… · Hide" above the lines); the hunk header stays free.
- `Calm Inspector Study.html` (2026-11-15, approved by Ralph the same day for Stories 10.42 + 10.43, own files `calm-study.jsx/.css`, styles from `inspector-study.css`): less on screen — folders show open/closed in their icon (no chevron, also in the Projects window), checkboxes only while the pointer or keyboard is in their pane (picked/half-picked always), no +/− counts, no status letter for a plain modification ("new" for an added file), no hunk header; the gaps between hunks are rows that open 20 lines up/down or all, their controls only while the pointer is in the code. Every pickable part has one box on its first changed line; a part that whitespace-only lines split (Ralph's boxed hunk under `-w`) keeps that one box, which takes all of it like the old hunk-header box, and hovering it lights up every line it takes.
- `Refs Study.html` (2026-11-15, own files `refs-study.jsx/.css`): tags on cards and in a rail view, bookmark/tag trees with search and row buttons, delete dialog, name field, move picker (a tag on a remote warns before it moves), search-row actions, top inset — approved by Ralph the same day for Stories 9.59, 10.44–10.47 and 11.26.
- `Inspector Extras Study.html` (2026-11-17, own files `extras-study.jsx/.css`, styles from `inspector-study.css`, `calm-study.css`, `settings.css`): the split button (Story 10.48 — composer Split ▾ Commit with bookmark chips and quiet menu lines, Squash on a click), file masks that hide files from the inspector's file list (funnel popover, hint row at the bottom), and Settings › Diff "Code font" + "Code size". Approved by Ralph the same day, with the study's proposals: sections 1–3 for Story 10.48, 4 for 10.49, 5 for 10.50.
- Graph layout engine: `graph-layout.jsx` (rows, lanes, columns, line routing, day axis; `computeLayout` + `groupStacks`), loaded before `graph-view.jsx` by every page that uses the graph. Layouts: **Free** (default; rows follow commit time, 16 units = 1 pitch, day labels on the dividers between days) and **Compact** (rows = generation depth). Both share one set of columns: switching only changes heights, never width or order. The old "Time" layout is gone.
- `Graph Lines Study.html` compares edge routing on the client's real layout (`graph-lines-study.jsx`, storage `zanshin.linesStudy.*`): A = the routing before, B = one line per parent→child pair (**shipped** — the team chose B), C = shared fork lines + own port per merge parent. Same engine as the client (`GraphLayout.reroute` draws A/C), plus Free/Compact, card width and a "+children" fan-out scenario.
- Before changing the app, archive the current state first: copy the floating client's files (`JJ Desktop Client Floating.html` + every file it loads) into `archive/vN <Name>/`.
- App icon / brand mark: **Nami** (the three gold waves on indigo, `icons/zanshin-icon-04-nami-indigo.svg`). The enso is retired.
- Accent system: gold = @ (working copy) + the one primary action; moon (`--accent`) = selection, focus, controls.
- Immutable commits: `immutable.jsx` holds `revset-aliases."immutable_heads()"` (store `zanshin.immutable`, mock evaluation, the page Settings › Project › Immutable commits); the graph re-evaluates `immutable` / `immWhy` from it after every edit. The card look is Hatched (settled, `FIXED.immStyle`); the floating client shows no ◆ — the hatch swatch `.ghatch` names immutable in peek, menu, inspector and settings.
- Windows (design system › Windows, sync #10): Settings and Projects are windows of their own above the project window (`windows.jsx` + `windows.css`, key window + inactive state); jj log Configurations and Push (`push-dialog.jsx` + `push.css`) stay sheets. The old dialogs (`settings.jsx › SettingsWindow`, `app-shared.jsx › HomeDialog`) remain only for the docked client and Search Study.
- Design system: lives in its own project, **Zanshin Design System** (`a33847c9-000b-4914-ae7f-6291f117e05f`), read-only from here. Whenever the floating client's visual system changes (new or changed component, token, pattern, rule), append a numbered entry to `DESIGN-SYSTEM-SYNC.md` in the same turn — what changed, which app files/classes, what the design system should add or update. Never edit old entries.
- Fonts: the client self-hosts Inter + JetBrains Mono via `fonts.css` → `assets/fonts/` (same files as the design system).
