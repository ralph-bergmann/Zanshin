### #11 · 2026-10-19 · Card menu: Revert (`jj revert -B @`)
The card menu (`…` on the card and right-click, `CardMenu`) gets **Revert** — for when the history should say that something was undone. State before the change: `archive/v15 Windows & Push/`.
Files: `graph-view.jsx` (`MENU_GROUPS`, `QA_ICON.revert`, `CardMenu` prop `revertOff`, `revertWhy`, `revertChange`), `graph-ops.js` (`GraphOps.revert`, `GraphOps.invert`). No CSS change — the row is a plain `.gmenu-item`.
- **Place** — the last group, above Abandon: the two ways to take a change back. Revert records the undo as a new change, Abandon erases the change. Revert is a regular row (not danger); label `Revert`, command column `jj revert -B @`.
- **Glyph** — a counter-clockwise circular arrow (16 grid, stroke 1.4, round caps), deliberately not the U-turn `undo` glyph, which stands for operations (Undo Timeline, toast Undo).
- **What it does** — jj's counterpart of `git revert`: `jj revert -r <change> -B @`. A new change with the inverse diff (+/− swapped, added ↔ deleted files) slots in between @ and its parents; @ keeps its own diff on top and stays @. Description per jj's default template: `Revert "<subject>"`, body `This reverts commit <commit id>.`
- **Availability** — changes in @'s history that change something, **immutable ones included** (pushed history can't be abandoned — the main case). Disabled for @ itself, for changes not below @ and for empty changes; the disabled row's tooltip (`title`) says why. The root keeps only "New change on top".
- **Feedback** — the clicked change stays still (FLIP anchor); the new change is born out of it (FLIP from its position, `born` edge draw) and scrolled into view if needed; toast *Reverted X — Y undoes it* with Undo (`jj undo`). An open inspector follows to the new change; a closed one stays closed.
