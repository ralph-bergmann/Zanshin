## Intent

**Problem:** Zanshin has its tokens and glass materials (11.1, 11.2; in `packages/zanshin_ui` since 11.14) but no controls: Yaru and Material cannot reach the DS's switch, checkbox, segmented control, select or menus (RC §2–§3), so every later story (11.3, 10.7, …) would rebuild focus, motion and semantics and drift. Nothing reviews them either, and the app's `marionette_flutter` 0.6.0 neither sees custom controls nor works with the installed `marionette_mcp` 0.7.0, which refuses any other binding version.

**Approach:** One state core on Flutter's widgets-layer primitives and the DS controls on it in `packages/zanshin_ui/lib/src/controls/`; a Widgetbook 3.25.0 catalogue at `app/widgetbook/main.dart` in its own `AppWindows` window (folders Controls, Materials, Windows, Icons; an Appearance addon; a Marionette extension that opens a path); `marionette_flutter` ^0.7.0 with one shared configuration for the app and the catalogue; the tooling rules in `project-context.md`. The run also settles three ledger items: I1 (Widgetbook's dev plugin in the release build — verify and report), I2 (the scroller paging value refreshes when Zanshin becomes active) and I3 (a Menu returns focus to its opener before its command runs).

## Boundaries & Constraints

**Always:**
- The requirement is epics.md Story 11.11 (:12841-12920) with its 2026-10-17 note; decisions 16.1, 16.3, 16.4, 16.10, 16.29–16.33 and 16.41 apply. Precedence: decisions in epics.md > DS tokens and CSS > a component's `.prompt.md` (for keys, `.prompt.md` > `.jsx`) > DS prose and cards. DS = `_bmad-output/implementation-artifacts/design_system/` (downloaded 2026-10-16).
- Every colour, size, radius, duration and curve comes from `ZsColors`/`ZsMetrics`/`ZsMotion`/`ZsElevation` `.of(context)` and `ZsType`. Literals only for component geometry the DS writes as CSS px (switch 30 × 18, checkbox 15/13 with radius 4.5/3.5, badge 15, row heights 28/34/36, the 4 px drag threshold, …), each with its `DS <file>:<line>` in a doc comment. No new name in any `toCss()` (the parity test rejects names the DS lacks).
- `lib/src/controls/` imports only `flutter/widgets.dart`, rendering, painting, services, gestures, scheduler, `dart:ui` and the package's own files; text entry is `material_ui`'s `TextField` with `decoration: null`. No visible Material, Yaru or Cupertino control. Designed visuals are a `RenderBox`/`CustomPainter` with text slots, not nested `Column`/`Row` trees.
- Every control: an optional `identifier` placed as `Semantics(identifier:)` on its own semantics node; an optional external `WidgetStatesController statesController`; implements the marker `ZsControl`; owns its cursor; takes reduce motion only through `ZsMotion` (durations and the `motion` factor) and the inactive window and increased contrast only through `ZsAppearance` and the resolved tokens.
- `zanshin_ui` gains no dependency; it never depends on `marionette_flutter`, `widgetbook`, `zanshin_core`, `inject_*` or the app. The app imports only `package:zanshin_ui/zanshin_ui.dart`.
- SPDX first line; page width 120; `dart analyze --fatal-infos --fatal-warnings` clean; every `@experimental`, `@Deprecated` or `@internal` use carries one explicit `// ignore:` with a `// WHY:`. Each default the story leaves open is marked "Claude's proposal (Story 11.11)" in a doc comment.

**Never:**
- No popover or menu placement against islands, insets, rail, calm scrolling or the per-window `BackdropGroup` (11.3); no window chrome kinds, dialog windows, per-window roots or window root keys (11.12); no menu bar (11.13); no Graph-folder demo host or any graph visual (10.1, Epic 10); no Settings, Projects or Push content.
- No Widgetbook 4, generator or Cloud; no Widgetbook `lightTheme`/`darkTheme`; no `AccessibilityAddon` or `DeviceFrameAddon` (deprecated); no `@internal` Widgetbook API (`updatePath`, `updateQueryParam`, `table`, …); no golden or snapshot tests; no Patrol; no separate widgetbook package; no `url_launcher` call in app code.
- No edits under `design/` or `design_system/`; no token value change; Yaru, `flutter_svg`, `main2`–`main4` and the mock UI stay (11.10); the marionette fork branch is not retired.

## Design Notes

**State core.** `ZsControlCore` is the one place for states, ring, cursor and semantics (RC §4, ≈ 40 lines plus the rules): Material's `WidgetStateMixin` is not in the widgets layer, and `FocusableActionDetector` takes no states controller, so the core keeps a `WidgetStatesController` (the caller's, or its own) in sync from `onShowHoverHighlight`, `onFocusChange` + `onShowFocusHighlight`, and a `Listener` for pointer down/up/cancel. macOS's highlight mode is always "traditional", so the ring would follow every focus; Zs controls therefore never request focus on a pointer press (`:focus-visible` semantics, RC `:148`), and text entry, which does take focus on click, shows its halo for any focus as the DS says. A forced `statesController` value wins for the catalogue's matrix (a forced `focused` counts as focus-visible). Toggles use `ToggleableStateMixin` and radios `RawRadio`/`RadioGroup` for their keys and focus groups, adding the core's ring, cursor and the checked/toggled semantics the mixin does not emit (`toggleable.dart:302-307`).

**Ring geometry.** CSS `outline: w solid; outline-offset: o` paints from o to o + w outward. Outside: o = 2, w = 2 (3 under contrast). Inside: o = −2, so the ring lies between −2 and 0; under contrast w = 3 would cross the edge and be clipped, so it moves to o = −3 (story item 1; Claude's proposal). Cards: o = 3. The radius follows the control's radius + o (never below 0). Entrance: from transparent at o + `focusSettle` × motion to rest on `durFocus`/`easeState` (`base.css:29-31`).

**Disabled with a reason** (`readme.md:136`, `base.css:38`): the reason lives on a wrapper that keeps hover (the tooltip) while the control itself ignores pointer and keys and leaves traversal; the semantics node is the control's (enabled false, hint), the tooltip's text joins the control's node (story item 1, KVS-9).

**Menu and I3.** `RawMenuAnchor` gives the overlay, outside taps, submenu trees and `onCloseRequested` for the exit; it restores no focus and its traversal shortcuts do not reach the overlay (`raw_menu_anchor.dart:771-801`, `:851-857`), so `ZsMenuAnchor` owns focus: it records the opener (the anchor child's focus node, else `primaryFocus` at open), moves focus into the menu's `FocusScope` (the highlight is the focus, no ring), handles keys itself, and puts focus back on the opener on Esc, on activation and on close by code. Activation order: blink (highlight off `durBlink`, on `durBlink`, input ignored meanwhile) → `opener.requestFocus()` → `onSelected` → close (`ZsSurfaceTransition` exit, `durExit`). Focus changes apply in a microtask, before the frame that builds a sheet the command shows, so `ZsSheet` records the opener, not the leaving row (`zs_sheet.dart:118`); `ZsSheet` stays unchanged. Safe triangle: from the pointer's last position to the submenu's near corners (`Menu.jsx:11`, `:48-53`). A keyboard-opened submenu highlights its first actionable row (epics; the DS's jsx does not). Typeahead: a single letter searches from the row after the highlight, a longer buffer from the highlight, wrapping, on `text` else the label (`Menu.jsx:63-79`).
