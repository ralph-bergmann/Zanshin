"Push" opens this sheet instead of pushing — for people coming from Git a push without a preview is dangerous: jj is not branch-based, one click can move several bookmarks and tags at once, backwards or sideways (rewriting the remote's history), to several remotes, or do nothing because no bookmark sits on @. The sheet is a surface for **exactly the parameters of `jj git push` (jj v0.46.0)**: the UI invents nothing and builds no sequence of commands.

~~~jsx
<PushDialog remotes={["origin", "upstream"]} defaultRemotes={["origin"]}
  bookmarks={[{ name: "feature/ZAN-412", tracked: true, from: "xyzrmwpo", to: "plkmnvxo", kind: "forward", inDefault: true },
              { name: "v1.5.0", type: "tag", from: null, to: "plkmnvxo", kind: "new", tracked: true, inDefault: true },
              { name: "review/ZAN-412-v2", from: null, to: "plkmnvxo", kind: "new" }]}
  change={{ id: "ovknlmro", generated: "push-ovknlmro", refused: "empty-description" }}
  onPush={(cmd) => run(cmd)} onCancel={close} />
~~~

- **Preselection = `jj git push` alone:** per remote, the tracked bookmarks pointing into `remote_bookmarks(remote=<remote>)..@` (configurable as `revsets.git-push`) **and the tracked tags**. Then the footer reads `jj git push`. Never while a refused ref is in that set — jj would refuse the whole push — then the footer names each ref.
- **Remotes:** chips for the configured remotes. The default needs no flag: `git.push` (one name, a list or a pattern — the sheet gets them resolved as `defaultRemotes`, so it can preselect several), else **the only remote**, else `origin`. Any other choice lists every chosen remote as `--remote <name>`.
- **Bookmarks and tags one by one:** ticking a row adds `--bookmark <name>` or, for a tag (marked TAG), `--tag <name>` (repeatable). A ref tracked nowhere is tracked by the push ("not tracked yet — the push tracks it"); one tracked on another remote is refused there instead. Bulk: *Tracked* `--tracked` · *All* `--all` · *Deleted* `--deleted` — each includes tags; *As jj git push* returns to the preselection. A bulk flag is written only while the selection is exactly that choice and holds no refused ref.
- **Several remotes:** jj classifies every ref per remote. One row per ref (its checkbox is the one flag, which goes to every chosen remote); under the name the row gets **one line per remote**, across the full width — remote · from → to · kind — so `main` can read *forward* on origin and *new* on upstream. In the preselection a remote that wouldn't get it says *not sent*.
- **A change:** "Push @ as a new bookmark" shows the name jj will generate (`templates.git_push_bookmark`, `push-` + short change id) → `--change @`; an edited name → `--named <name>=@`. jj checks its commit like any other: an @ without a description (the normal case) reads *Refused — ovknlmro has no description* right under the label line, the checkbox is disabled, and a short **Allow** chip at the end of the label line (its title: `--allow-empty-description`) enables it — then *Allowed — … · pushed with `--allow-empty-description`*, and the flag joins the command once the change is ticked. Several reasons: the long chips (*Allow empty descriptions* …) in a row under the reason, as for refs. The name field and its line (*The name jj generates …*) stay below — as the floating client does.
- **What happens** is the `--dry-run` result per ref and remote: **new** (green) · **forward** (quiet) · **backwards** · **sideways** · **delete** (warn, with the warning glyph). jj checks each update against what you last fetched (the lease); a warning line sums the three up. Up-to-date refs aren't listed.
- **Refusals** — jj refuses the *whole* push while one is in it, so a refused row can't be ticked. It says why, with jj's words, the change id, and several reasons at once (*has no description and has conflicts*):
  - allowable commit checks — no description, private (`git.private-commits`), conflicts: an *Allow* chip per reason (inline when there is one) → `--allow-empty-description` · `--allow-private` · `--allow-conflicts`; one flag covers every commit, so allowing it in one row allows it in all;
  - without a switch, no chip — the reason and the command jj's hint names: *has no author and/or committer set* · *main is conflicted* / *main@origin is conflicted* · `jj git fetch` · *an untracked main@upstream exists* · `jj bookmark track main@upstream` · *refusing to create new remote bookmark main@upstream — it is tracked on origin*.
- **Footer:** the exact command (mono well — "Zanshin never hides what it runs"), *Checked with --dry-run*, Cancel, **Push** (the gold primary).
- **States:** nothing to push (one sentence, Push disabled) · pushing (progress in the footer, Push busy, Cancel inert) · errors that stop everything, in a red note with the remote named: network, credentials (Try again) · **done — some pushed, some not.** jj checks the lease ref by ref, pushes the rest, records the operation and ends with "Failed to push some bookmarks". The sheet stays: *Pushed 2 of 3 — the rest stayed as they were. The push is recorded, so Undo works as usual.* Per remote line: **pushed** · **moved on origin** (the lease: *origin has moved main since the last fetch. Fetch, point main where it should be, then push again.* — after the fetch the bookmark is often conflicted, so the fetch alone isn't the fix) · **rejected** (the remote refused — permissions, hooks — with its message). *Fetch* (`jj git fetch --remote …`) where a lease failed; **Done**.
- **After:** the result toast as usual (*Pushed 2 bookmarks to origin · Undo*). Undoing a push warns as the CLI does: *Undoing a push operation often leads to conflicted bookmarks.* with **Redo**.
- Keyboard · VoiceOver · Reduce motion: focus starts on Push (Done); Tab cycles inside the sheet; Space toggles the focused row; ↩ pushes (not from the name field), in *done* ↩ is Done; Esc and Cancel cancel (not while pushing) — **a click on the scrim does nothing** (a sheet never closes by a click beside it; a hand-made selection isn't lost); focus returns to the Push button · a modal dialog "Push"; rows read as checkboxes with name, TAG, from → to and the kind per remote; refusals with their reason, results and errors are announced · the sheet fades in place (its 8px rise × `--motion`).
