# Zanshin Design System

Zanshin (残心 — "the lingering mind": the calm attention that stays after an action) is a **desktop client for Jujutsu (`jj`)**, the Git-compatible version control system. Its one idea: **the change graph owns the window**. Every control floats above it on glass islands; the working copy `@` is always findable; every edit can be undone.

This design system captures the reference surface — **"JJ Desktop Client Floating"** — as tokens, fonts, brand assets, React components and a click-through UI kit. The product is being designed for a Flutter/Dart implementation (the source docs ship Dart recipes for the lane gradient, splash screen and loader), so values here are exact and platform-neutral.

## CONTENT FUNDAMENTALS

**Voice.** Quiet, exact, a little dry — a tool that trusts you. It never explains what you can already see ("nothing that explains itself"). UI copy is English — the splash status lines too (`Loading repository…`); only the design notes are German, and German strings belong to the localisation.

**Casing.** Sentence case everywhere: *New change*, *Squash into parent*, *Move only this change*, *Detailed cards*. Section labels are written in sentence case and set in caps by CSS (`Graph view`, `Recent`, `While you scroll`). Product nouns keep their case: jj, @, revset, bookmark.

**Verbs first, jj underneath.** Labels are short verbs; the exact jj command is always one hover away — in `title`, a menu's right column, or a footer: *Move here* → `jj rebase -s ovknlmro -o vruxwmqv`; *Split* → `jj split -r plkmnvxo -i`; *Fetch — jj git fetch*. The search footer shows the full command a filter will run (`jj log -r 'author(exact:"Lena König")'` · *Filter ↵*) or says what a go-to does (*Selects the change — the graph stays as it is* · *Select ↵*). Zanshin never hides what it runs (Settings even shows the config key: `revset-aliases."immutable_heads()"`).

**Every command is real.** A jj command in any UI text — tooltip, menu column, footer, empty state, command well — exists in **jj v0.46.0 exactly as written, with exactly those options**. No invented verbs or flags (`jj git push --allow-backwards` and `jj workstream new` were both made up — `--allow-backwards` itself is real on `jj bookmark move`, and Zanshin uses it there, for a bookmark dragged backwards). It follows from "Zanshin never hides what it runs": a command that doesn't exist can't be what Zanshin runs. And the UI never composes a sequence of commands of its own.

**Person.** Mostly impersonal; "you" only when it helps: *No changes yet — whatever you edit in your editor lands here.* · *Stays here to keep working.* No "we", no "please", no exclamation marks.

**Empty states** are one sentence, often with the command that fixes it: *No bookmarks yet. Create one with `jj bookmark create <name>`.* · *No open reviews.* · *A merge — no changes of its own.* · *The root of all history.*

**Feedback** is past tense, verb first, ids in mono: *Moved ovknlmro onto vruxwmqv* · *Squashed … into …* · *Split … — the rest is now …* · *Committed … · “feat: …”* · *Reverted … — … undoes it* — always followed by **Undo**.

**Hints** chain with middots: *Click: details · Double-click: jj edit · Drag: onto another change · Right-click: actions*. Warnings are one word in the warn colour (*backwards*).

**Punctuation & glyphs.** Ellipsis `…` on items that open something (*Settings…*, *All Projects…*, *Describe…*); curly quotes around messages (“…”); real minus `−` in counts (`+42 −7`); `·` as separator; `‥` for stack ranges; `↑2 ↓3 ✓ ↕` sync state; `@` the working copy; `$` marks a jj log variant that draws the graph (search menu rows, the search pill at rest on a variant). Shortcuts are plain text in menus (`⌘,`), key caps only in prose. Immutable has no glyph and no colour: the hatch on the card is the marker, `HatchSwatch` names it beside the word — the `◆` is retired (only people who know jj read it).

**No emoji.** Never.

**Ids.** Change ids print with the unique prefix bold: **ov**knlmro. Short form 5 chars on cards, 8 in menus, toasts and commands.

## VISUAL FOUNDATIONS

**Mood.** Night indigo with warm gold — calm, deep, instrument-like. A light "paper" theme mirrors it in warm off-white and umber. Night is the brand default; the splash is always dark.

**Colour (see `tokens/colors.css`).**
- *Canvas* — two static shaders, no images: linear 165° `#1a2038 → #12162a → #0e1224` plus a flat radial indigo lift top-left (`rgba(96,120,178,.24)`). Paper: `#f7f4f0 → #f0ece7 → #e8e3dd` with a gold lift.
- *Gold* `#dca85b` is spent twice per screen at most: `@` (as saffron `oklch(78% .16 75)`) and **the one primary action** (gold-tinted glass button). The token is split by role: `--primary-action` (the button) and `--at-chrome` / `--at-chrome-edge` (the @ pill edge, the minimap day pill and connector); the legacy alias `--fl-gold` is retired. Everything else is quiet.
- *Moon* `oklch(80% .07 272)` — the interactive accent derived from the canvas lift: selection rings, focus, switches, sliders, menu hover (filled, with `--accent-ink` text), checkboxes, hunk headers, "M" status, and in the search field: its focus ring, the pill while anything but the default search shows, the highlighted suggestion and the match underline. Never for primary actions; gold stays with `@`.
- *Text ladder* `#e7e9f2 / #b3b9d0 / #9299b4 / #8189a5` — every step ≥ 4.5:1 on the card surface.
- *Semantic* add `#4ade80`, remove `#f87171`, conflict/warn amber; darker on paper. Paper saffron, co-text, conflict and warn are sRGB-safe hex values (the old oklch values sat outside sRGB and P3). Every colour token is a fixed hex or rgba value — oklch only in the comments — so Flutter takes each one 1:1. Moon as data — status M, the hunk band, remote — has its own fixed tokens (`--status-m`, `--hunk`, `--hunk-bg`, `--remote`); project status dots are tokens too (`--proj-*`, darker on paper; `--proj-stale` for a stale working copy).

**Type (see `tokens/typography.css`).** Inter for UI; **JetBrains Mono for anything jj prints** (ids, revsets, commands, paths, diffs, counts); Shippori Mincho only for 残心. A dense desktop scale: 9.5 · 10.5 · 11 · 11.5 · 12 · 12.5 · 13 · 15 · 17 · 18px — ten tokens (`--fs-2xs` … `--fs-2xl`), and components use nothing else. Base 13px; inspector title 18/600, −0.012em; caps labels 10.5/600 +0.1em. The wordmark is strokes, not a font. Client and design system self-host the same woff2 files, so both render the same faces.

**Space & layout.** One 12px rhythm for the chrome: islands sit 12px from the window edge, 12px apart and **12px after the traffic-light block**. The traffic lights are the system's and Zanshin never moves them; it reads their frames at runtime and derives the bar: **first island x = block end + 12**, the bar (44px) **centres on the block's centre line**, content starts at **bar bottom + 12**. Reference (macOS 27.0.1, standard buttons, the app's toolbar, measured): 14 × 14pt, pitch 23, block 60 wide at x 19–79, centre y 26 → first island 91, bar 4–48, content 60 (`--tl-*`, `--chrome-first-x`, `--chrome-bar-y`, `--chrome-top`). Without a toolbar the system puts them at x 9–69, y 16; before macOS 26 they were 12pt at a 20pt pitch — no fixed number is "native", so the rule is relative. Full screen: no block → first island 12, bar top 12, content 68 (`[data-fullscreen]`). The rail is 52 wide at x 12, content starts at 76. Inspector 460px, pinned panel 300px — both resizable at their edge toward the graph (380–720 · 240–440, `ResizeEdge`, remembered app-wide; at least 320 of graph stays visible) — minimap 134px. Cards 240 × 62 (detailed) / 40 (compact), lanes 56px apart, rows 48px apart. The graph fills the window and pans freely; the top bar reads **Place · View · Action** on a grid of `minmax(max-content,1fr) minmax(0,max-content) minmax(max-content,1fr)` — on narrow windows the centre gives way, the side groups keep their size. The View capsule reads `[menu ▾ | query | ✕] · gap legend · count · View options`.

**Control heights.** One scale for everything that can share a row: 22 · 26 · 30 · 36 · 44 (`--control-xs` … `--control-xl`, ≈ ×1.2 a step). 30 is the default — buttons, fields, selects, the search field, settings controls, panel close buttons; 36 belongs to the islands (icon buttons, the bar's search field, @ pill) and to title fields, settings tabs and the toast; 44 to the top bar and its primary action; 26 to chips and segmented controls; 22 to the small ones. A control inside another is the outer height minus twice the inset — the concentric rule again (chip 26 → its ✕ 20 · toast 36 → Undo 26 · tabs 36 → 30). Lists keep their own row heights: menus 28, drop menu 30, suggestions 34, options 36, settings 46.

**Backgrounds.** No photos, no patterns in the app. The floating client drops the docked client's 24px dot grid — the canvas is clean. The only ornament is the wave motif, large and at 5% on the splash.

**Material.** Glass islands: `--fl-bg` (66% indigo) + 46px top sheen + `blur(18px) saturate(1.4)`, 1px `--fl-border`, `--fl-shadow` (inset 1px highlight + soft drop). Stronger glass (86%, blur 22) for the inspector and minimap; solid `#1a1f35` for menus and popovers — **one material** for every menu, popover, callout and the peek: `--fl-sheen` over `--fl-bg-solid`, 1px `--fl-border`, `--shadow-menu`, 13px with 8px rows at a 5px inset (`--surface-menu` points at it; `--bg-elevated`, `--shadow-popover` and `--shadow-callout` are retired). Blur appears only on floating chrome and sheet scrims. **The 18px sheet over a blurred scrim is only for short modal tasks** — there are two: ConfirmDialog and Push. A click on the scrim does nothing (a macOS sheet never closes by a click beside it); Esc and Cancel cancel. Settings, Projects and jj log Configurations are **windows of their own**: no scrim, no 18px radius, no `--shadow-dialog`, no entrance — the system draws corners, shadow and appearing; Zanshin fills them borderless and opaque (`--fl-sheen` over `--fl-bg-solid`, no vibrancy). Reduce transparency is a token delta (`tokens/transparency.css`): every glass surface turns solid, nothing blurs — components carry no rule of their own.

**Cards.** Solid `--card-solid`, 10px radius, 1px `--border-strong`. Hover → `--card-solid-hi` + brighter border. Selected → moon border + 3px ring. `@` → saffron border, diagonal saffron wash, 1px + 4px glow. Stacks show two offset card edges beneath. Bookmarks ride the top edge as a pill; the ••• button sits on the bottom edge on hover. **Immutable** → the normal card with a 135° hatch, 1px every 6px in `--hatch` (7% of `--text`) — kept on hover, selection, open menu and drop target; stacks follow; the subject stays `--text-muted`. No colour, no ◆: gold stays with @, moon with the selection.

**Corner radii — concentric.** Inside a rounded container a radius is the container's minus the inset: island 14 − 4 = 10 (controls in islands) · menu 13 − 5 = 8 (its rows) · rail 16 − 5 = 11 (rail buttons) · tab bar 10 − 3 = 7 (its thumb). The scale, all tokens: 3 key caps · 4 @ badge · 5 tags · 6 segments · 7 chips, tooltips · 8 rows, fields, menu items · 9 buttons · 10 cards, controls in islands · 11 rail buttons · 12 wells (diff block, settings groups) · 13 everything that floats for a moment (menus, popovers, suggestions, callouts) · 14 top-bar islands · 16 inspector, rail, panels · 18 dialogs · pill for anything that is height / 2. Components never write a radius as a number (only the checkbox's 4.5 / 3.5, its own geometry).

**Borders & lines.** Hairlines at 7–14% white; graph edges 1.5px at 34% (`--edge`), 72% on hover, 10px elbows; the `@` path saffron 2.25px with a soft glow. **One line per parent → child pair:** its own exit on the parent's top edge and its own entry on the child's bottom edge (first parent: bottom centre; other parents beside it, farther = farther out). Forks turn just above the parent, merges just below the child; horizontal runs stack 3.5–6px apart and nest instead of crossing; a lane that is taken (in Free also: a card in the way) sends the line up the gutter between columns. Exit fan-out depends on the card width: 12px apart, squeezed down to 7px, then the outermost lines share one exit and split above the card. Crossings break the horizontal line (12 × 10, ≥ 12px of line to the next bend or card), else the vertical one. Hidden history = dashed edge broken by two slanted cuts that keep 12px of line to cards; end of history = dashed stub + cuts + "~ elided".

**Shadows.** Islands: inset top highlight + `0 14px 36px -12px` drop. Menus `0 24px 60px -16px`; dialogs `0 40px 100px -24px`. Paper uses umber shadows instead of black.

**Layers.** One order, as tokens: the graph · `--z-chrome` 20 (islands, rail, panels, minimap, toast, the stale notice) · `--z-preview` 40 (peek, stack list, callouts) · `--z-dialog` 50 (scrim + modal sheet — only the sheets) · `--z-menu` 60 (menus and popovers — above the sheet that opened them) · `--z-drop` 70 · `--z-tooltip` 80 · `--z-drag` 90. Windows of their own (Settings, Projects, jj log Configurations) are ordered by the system, above the project window even in full screen (Configurations: while Zanshin is active). Numbers inside a component (1–3) stay local.

**Interaction states.** One model for every control — see **Control states** below and the cards *Controls — state model* / *state matrix*. Rest → hover → pressed is one fill step each (`--fl-hover` 7% → `--fl-on` 11% → `--fl-press` 15%), instant on press, no shrink. Focus = 2px `--focus-ring` outline 2px outside (rows inside). Disabled = .4. Command-menu highlight fills the accent with ink text; danger rows tint red. Danger buttons stay quiet until hover.

**Motion** (`tokens/motion.css`). Three curves by job: `--ease-state` (.25,.1,.25,1) for colour, opacity and outline; `--ease-glide` (.32,.72,0,1, "fast out, long settle") for anything that moves, resizes or enters; `--ease-exit` (.4,0,1,1) for leaving; `--ease-linear` for the spinner and sweeps. Durations are tokens only, in two families. **Fades** (colour, opacity, the fade of every entrance and exit): press 0 · hover / every colour change 120 · focus 160 · menu in 110 · pop 160 · exits 120 / 180 · panels 200 · sheets 220 · slide 260 · birth 540 · flash 2400. **Movement** (position, size, rotation, stroke drawing): nudge 120 · toggle 180 · expand 200 · move 260 · flip 460. Waits and holds are tokens too: tooltip 700 (warm window 600), peek 450, stack list 380, callout 90 / 200, drop menu 520, submenu 150 / 300, skeleton 150, scrollbar hide 800, typeahead 600, toast hold 6500, "Copied" 1200; **calm scrolling** — the floating chrome steps aside on `--dur-calm-out` 180 (`--ease-exit`) and returns `--delay-calm-return` 650 after the last scroll, over `--dur-calm-in` 340 after `--delay-calm-in` 60; the traffic lights and the minimap stay. **Reduce motion is defined by property, not by animation:** colour and opacity keep their tokens (every fade stays, every exit fades out, the edit flash stays a colour fade); movement, size, position, rotation and stroke drawing go to zero — `--motion` 1 → 0 multiplies every keyframe distance, scale and angle, and the five movement durations → 0ms. The one delta lives in `tokens/motion.css`. Exceptions, both information: the spinner keeps turning; sweeps (skeleton, indeterminate bar) pulse instead. The Nami loader: one gaussian swell runs through the waves (1.3s + 0.55s pause).

**Cursor.** On a Mac the arrow is the cursor: no pointing hands on controls (no `cursor:pointer` in the components — buttons, switches, segmented controls, cards, toggles all keep the arrow), no open hand on the canvas; the closed hand (`grabbing`) only while you hold the canvas; the **I-beam** over text entry (fields, areas, the search inputs — read-only fields too, they are selectable); **`progress`** over anything `aria-busy`; the **resize** cursor over a `ResizeEdge` (`col-resize`, one-way at a limit — AppKit's resizeLeftRight / resizeLeft / resizeRight). Links with an `href` are the one exception.

**Time in the graph.** Two layouts in View options: **Free** (default) — commits close in time stand close together across branches; gaps grow with the time between commits, log-damped and capped at 3 pitches; an edge is always at least one pitch — and **Compact** (rows = generation depth). Both share their columns: switching only moves cards up and down. Free has a **day axis** without a gutter: a dashed divider (`--border-strong`, 2 6) between two calendar days, and each day's label (mono 11 pill) on the divider below that day's first commit, at the left edge, sticky — reading upward, "this day starts here"; the oldest day's label sits below its first commit. Cards show relative age (`now`, `3h`, `2d`, `Sep 19` for older). Day labels — axis and minimap — are calendar days only: **Today**, **Yesterday**, then dates (`Sep 23` …), newest at the top, never relative values. In Free the minimap uses the axis's labels and its pill names the day the viewport centre is in; in Compact a label appears only when its day is older than the one above it.

**Where settings live.** How the graph looks lives with the graph: the **View options** popover in the top bar (Layout Free · Compact, Detailed cards, Group stacks, Card width). What the graph shows is the search field's job; jj log configurations are made and edited only in the **jj log Configurations** window (search menu › Edit Configurations…, ⌥⌘L), which also sets the default search. Set-and-forget settings share one **Settings window** — a window of its own — with a tab per scope: **General** (appearance, scrolling, diffs, identity; `~/.config/jj/config.toml`) and **Project** (remotes, trunk, immutable commits — a page of its own inside the tab —, project email; `.jj/repo/config.toml`), reached with ⌘, — every row that shows ⌘, does what ⌘, does (the tab shown last) — or with the two rows that pick a tab and show no ⌘,: Project Settings… (project capsule) and the popover's last row, Appearance, diffs and more (General).

Zanshin draws every control itself (Flutter, no Material, no Yaru), so this section is the whole spec: what isn't here, the code would have to guess. Tokens: `tokens/states.css`; specimens: *Controls — state model*, *state matrix*, *micro-animations*.

**Seven rules.**
1. **Focus — one rule.** 2px `--focus-ring` outline, 2px outside, keyboard only (`--focus-w`, `--focus-offset`), at specificity (0,2,0) so a component's rest `outline:none` never hides it. Exceptions, each for a reason: rows in lists, menus and scroll areas, flush segments, rail buttons, scroll viewports and anything inside a clipping well draw it 2px inside (`--focus-offset-inset`) · graph cards 3px out (`--focus-offset-card`) · text entry shows edge + halo on any focus · open-menu rows (and the menu container) show focus as their highlight. A control that appears only on hover (•••) also appears with focus. The list of inside-ring components lives in `components/base.css`.
2. **Disabled — one value.** `--disabled-opacity` .4. With a reason worth knowing, `aria-disabled`: looks the same, does nothing (no hover fill, no press, no pointer or key activation, no Tab stop), the reason on its wrapper; VoiceOver reads "dimmed" with the reason. Flutter: `Tooltip(message: reason, child: IgnorePointer(…))` + `Semantics(enabled: false, hint: reason)`.
3. **Selected — where vs. what.** `--fl-on` = where you are (navigation, tabs, segments, the file whose diff shows). `--accent-soft` = what you picked among data (a project, a configuration) and the keyboard row of a field-attached list. Accent edge + ring = the selected change. What a list *shows* is a check, never a fill.
4. **Menu highlight — two kinds.** Command menus (context, drop, project, select list, text menu): focus moves into the menu and ↩ runs a command → solid accent + ink. Field-attached lists (search menu, suggestions): focus stays in the field (`aria-activedescendant`), ↑↓ move the keyboard row → `--accent-soft` + accent icon; hover is `--fl-hover` and never moves the keyboard row; what the graph shows carries a check. Danger rows: red at rest, a red tint on highlight (`--danger-hover` .10 — red text 4.5:1 even under a menu's sheen) — never a solid red fill.
5. **Motion — curves by job, durations as tokens.** State changes (hover, release, focus colour) `--ease-state`; movement and entrances `--ease-glide`; exits `--ease-exit`; sweeps `--ease-linear`. Press is instant. A transition times colour with a fade token and geometry with a movement token, never one token for both; keyframes write their distances × `--motion`. Reduce motion: movement → 0, colour and opacity stay.
6. **Tinted on-states** carry coloured text only on the plain tint; on hover and press the tint steps up and the label turns `--text` (coloured text on a stronger tint falls under 4.5) — and so does a tint that sits on another fill: the scope pill (its tint over the capsule's `--fl-hover`, where accent text measured 3.7–4.6) reads `--text` at rest too; its icon keeps the accent (non-text, ≥ 3:1).
7. **Secondary text on a fill steps up a rung** (see the table) — so faint and dim keep 4.5:1 wherever they sit.

**The gold primary — one recipe.** sm, md and lg share fills `--primary-fill-a/-b` (22% / 8% of gold), a 1px inset ring `--primary-ring` (55%; 80% on paper for 3:1), hover `-hover` (30 / 12, ring 100%), pressed `-press` (38 / 17, ring 100%), disabled .4. lg only adds the island glass and `--fl-shadow` underneath. The Configurations dialog's OK uses the same tokens (no more border vs. inset ring). The **destructive** button is the same build in red (`--destructive-*`) and is the one primary of a confirmation.

**Keyboard · VoiceOver · Reduce motion** — one line per control, in every `.prompt.md` (Dialog and Popover: Esc, initial focus, focus trap, focus return, a scrim that takes no clicks · ResizeEdge: arrows, Home End, ↩ the default · ScrollArea: keys, track click, both axes, overscroll · Menu and ProjectMenu: ↑↓ Home End, typeahead, submenus, blink, closing · ProjectRow: a tree, one Tab stop · Tooltip: flip and clamp at the window edge · Switch, Chip, Link, FileRow, Slider, Select …).

**Decision: C1 + D.** *Multicolour* = Zanshin as designed (moon). A named choice in System Settings › Appearance › Color re-colours **only the moon role** — selection, focus, switches, checkboxes, radios, sliders, menu highlight: exactly the surfaces macOS gives its accent. Settings › General › Appearance gets **Accent colour: Follow macOS · Zanshin** (default Follow macOS). Gold — the @ working copy, the one primary action, the brand (Nami, wordmark, splash, the paper canvas lift) — and every data colour stay fixed (HIG: colours that carry meaning are exempt).

Why not C2 (the primary follows too): it would change nothing for Orange and Yellow (≈ gold already), make the primary read as destructive under Red, lose its emphasis under Graphite, and merge it with selection under Blue and Purple — breaking "moon is never a primary action" for little recognition gain. **"Dieser Mac" (iMac colours)** gets no family of its own. ## WINDOWS

## PUSH

Push opens a sheet (`PushDialog`) instead of pushing: jj isn't branch-based — one click can move several bookmarks and tags, backwards or sideways (overwriting the remote's history), to several remotes, or do nothing because no bookmark sits on @. The sheet is a surface for exactly the parameters of `jj git push` (v0.46.0).

- **Preselection** = `jj git push` alone: per remote the tracked bookmarks in `remote_bookmarks(remote=<remote>)..@` (`revsets.git-push`) **and the tracked tags**. **Remotes:** `git.push` — a name, a list or a pattern — else the only remote, else origin; those need no flag and may be several (`defaultRemotes`), any other choice lists each as `--remote`.
- **Rows:** bookmarks and tags (marked TAG) → `--bookmark` / `--tag` (a ref tracked nowhere gets tracked) · bulk `--tracked` / `--all` / `--deleted`, tags included · a change: `--change @` with the generated `push-…` name shown in advance, an edited name → `--named <name>=@` · per row the `--dry-run` kind: new · forward · backwards · sideways · delete (the last three warn). **Several remotes:** one row per ref, one line per remote — the kind there, *not sent* where the preselection doesn't send it, *refused* where that remote refuses it.
- **Refusals** — jj refuses the *whole* push while one is in it, so a refused row can't be ticked, and the bare command or a bulk flag is never written while it would carry one. With a switch: no description · private · conflicts → an *Allow* chip per reason, `--allow-empty-description` / `--allow-private` / `--allow-conflicts` — the change (@) too, where no description is the normal case. Without one, jj's reason and the command its hint names: no author and/or committer · conflicted here or on the remote (`jj git fetch`) · an untracked `<name>@<remote>` (`jj bookmark track …`) · tracked on another remote ("refusing to create new remote bookmark"). Several reasons at once ("has no description and has conflicts").
- **Footer:** the exact command, Push (gold), Cancel; a click beside the sheet does nothing. Nothing to push · pushing · network and credential errors (Try again).
- **Partial success** — jj checks the lease ref by ref, pushes the rest, records the operation and ends with "Failed to push some bookmarks": the sheet stays (`state="done"`, `results`) — *Pushed 2 of 3*, per remote line **pushed** · **moved on origin** (the lease; jj's hint: fetch, point the bookmark where it should be, push again — after a fetch it is often conflicted) · **rejected** (permissions, hooks: the remote's message); Fetch where a lease failed; Done. The push is recorded, so Undo works.
- **After:** the result toast; undoing a push warns as the CLI does (*Undoing a push operation often leads to conflicted bookmarks.* · Redo). Cards *Push dialog — Night / Paper*.

## ICONOGRAPHY

- **Own line set, one grammar.** 16 × 16 canvas, live area 1–15 (strokes and caps included), one stroke 1.5, round caps and round joins — no pointed tips anywhere —, `currentColor`. Solids only where meaning needs one (filled bookmark, the half-filled Auto, dots r 1.25). Shared parts: graph nodes r 1.75 · cards 11 × 3.5 with radius 1.5 · rect corners 1.5 · arrowheads with 3-unit legs (3.5 for single arrows and chevrons) · **the `!` — one drawing in `alert` and `conflict`: a 2.25 bar, 1 unit of air, a dot r .85** · separate parts keep at least 1 unit of air between their strokes — nothing touches unless it is meant to join (merge-new: the plus's stem is the merge's child line, on purpose). One exception the shape forces: inside the warning triangle the bar's top keeps .5 to the sloped sides. 59 glyphs, every one a file in `assets/icons/ui/` — the source; `Icon` is generated from them and `assets/icons/glyphs.json` lists the names and the retired aliases (keep it in step with every new, renamed or removed glyph — the app checks its icon list against it). No CDN set, no emoji.
- **No icon font.** The Flutter app renders `assets/icons/ui/*.svg` — precompiled at build time (`vector_graphics_compiler`) and tinted in one colour at runtime. The card *Icons — on the grid* shows every glyph whole at 4× with its grid and live area.
- **File rules** — the build compiler silently drops what it doesn't know (a `<style>` block would turn every stroke into a black area), so every file keeps exactly this form: the root `<svg xmlns="http://www.w3.org/2000/svg" width="16" height="16" viewBox="0 0 16 16">` holding exactly one `<g fill="none" stroke="currentColor" stroke-width="1.5" stroke-linecap="round" stroke-linejoin="round">`; inside only `path`, `circle`, `rect`, `line`, `polyline`, `polygon`, `ellipse`; areas `fill="currentColor"` with `stroke="none"` where there is no outline; presentation attributes only — no `<style>`, `class`, `style=""`; no `id`, `transform`, `opacity`, `mask`, `clipPath`, `filter`, gradients, `<use>`, `<symbol>`, `<defs>`, `<image>`, `<text>`, `<title>`, `<desc>`, comments; the only colour is `currentColor` (the app tints the whole glyph — a second colour would be lost); coordinates with at most 2 decimals; **`rx` / `ry` at most half the shorter side** (browsers clamp a larger radius, `vector_graphics_compiler` doesn't and draws overlapping ends — `move-only`'s 2.5-high cards had 1.5, now 1.25); no metadata. Every current file follows them.
- **Sizes are tokens** (`--icon-*`; `Icon` takes the same names): xs 10 (the ✕ inside chips and fields) · sm 12 (rows, chips, flags, card meta, close buttons) · md 14 (buttons, menu and list rows) · lg 16 (panel headers, the primary action — the drawing grid 1:1) · bar 17 (top-bar icon buttons) · rail 19 (rail). Nothing in between. Colour is the text ladder (`--text-dim` at rest, `--text` on hover); semantic colour only for meaning (conflict amber, viewed green).
- **Two arrows back, two meanings:** the U-turn (`undo`) is for operations — the Undo Timeline, the toast's Undo, ⌘Z (`jj undo`); the counter-clockwise circular arrow (`revert`) is a change's inverse — the card menu's Revert (`jj revert -B @`). `history` (a clock) is neither.
- **Immutable has no glyph**: the card's hatch is the marker and `HatchSwatch` (the hatch on a 12px card in miniature) names it wherever the word is written — never a ◆.
- **Unicode as type, not icons**: `@ ↑ ↓ ✓ ↕ ‥ · −`, and the search menu's `$` row glyph (mono 600 13px, `--text-dim`, moon when selected).
- **Brand mark**: Nami — three gold waves (`#f4cf80 / #dca85b / #b58346`) on an indigo squircle (radius 58/256). Drawn heavier at chrome sizes (≤ 48px). Use `NamiMark` or `assets/app-icon/zanshin-icon-nami-indigo.svg`; never redraw it. The ensō studies (#01–#03) are retired and not shipped.
- **Wordmark**: ZANSHIN in monoline strokes, A without crossbar, wide tracking — gold gradient on night, `#26304d` ink on paper, white on black (`assets/zanshin-wordmark-*.svg`, `Wordmark`).

### Intentional additions

None of the components above are inventions — each maps to a CSS family of the floating client (`.gcard`, `.gins-flag`, `.gck`, `.gset-row`, `.gdrop`, `.gpm`, `.gtoast`, `.gpeek`, `.gghost`, `.ghunk`, `.home-row`, `.gs-*`, `.rsd-*`, `.gtime`, `.ghatch`, `.gmenu-note`, `.gset-nav`, `.gimp-*` …). Packaging choices: `Icon` bundles the SVG set plus the client's inline glyphs; `GraphEnd` is split out of `GraphEdge`; `GraphPorts` exposes the router's constants and fan-out functions (graph-layout.jsx) so layouts can place exits, entries, tracks and bridges exactly; `OptionLink` names the view menu's "Settings…" row; the graph search is split into the field, its menu and its suggestion parts so each state can be composed.

**Control library** (`components/controls/`, decided with the Flutter port: Zanshin draws its own controls, no Material, no Yaru — so every state the code needs is specified here). `Radio`/`RadioGroup`, `Tooltip`, `Spinner`, `ProgressBar`, `Skeleton`, `Chip`, `Badge`, `Link`, `Disclosure`, `ScrollArea`, `ConfirmDialog`, `Presence`, plus new variants of existing parts (Button `destructive` / `busy` / icon-only, IconButton `badge`, Menu check items / submenus / headers / shortcuts, Toast `warn` / `error`, custom `Select`). The floating client doesn't show them (yet) because its surfaces haven't needed them: it has no radio choices, no irreversible local action that would ask first, no long operation with measurable progress, it uses the HTML `title` instead of tooltips and a native `<select>` in Settings. The UI kit uses Select, the Fetch badge and the accent setting; the rest live on the Controls cards until the client adopts them. A status pill is not a control of its own: in the inspector header it is `Flag` (neutral · @ · warn), in the Projects tree the saffron **OPEN** caps marker of `ProjectRow`.
