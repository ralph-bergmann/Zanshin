## Intent

**Problem:** The app's windowing knows only the project window: `AppWindows` creates `WindowController`s with the main chrome, ends the process when the last window goes, and no dialog window, per-window root, key status, Projects launch window, close intercept or reopen handling exists — so 11.5/11.6 left Projects unreachable (ledger I4–I6), nothing drives `ZsAppearance.inactive` (I3), and Settings' content-sized frame (I1) has no native support.

**Approach:** Generalise `AppWindows` to parentless dialog windows (one per key, own minimum, close intercept, keep-alive exit rule, close guards), parameterise the runner chrome (`main | secondary`) and frame store (full / position-only with the top held, centred first placement, floating-while-active level, `isRestorable = false` everywhere), make `zanshin_shell` act on every window, give every window a keyed per-window root fed by an active-window tracker, and add a coordinator that owns the launch window, Projects ↔ project-window transitions, the red button, the Dock reopen and the quit hook; the catalogue gains the Window scaffold windows that exercise each native mode.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Launch, project stored | `openProject` set, its folder exists | first window `main` (project window); reopen runs in parallel; once shown, a project is open → nothing more | — |
| Launch, nothing to open | `openProject` null, or its folder is gone | first window `projects`, built before `runWidget`; no project window | the missing entry is cleared/marked by `reopenLast` as today |
| Launch, reopen fails | stored folder exists but holds no jj workspace / the open fails | after the first window is shown: Projects opens, then the project window is destroyed; no exit | failure stays in `lastFailure` (logged by code) |
| Close project | red button on `main` with a project open | close guards pass → `closeProject()` → Projects opens → `main` destroyed (and `revset-configs` if open); app keeps running | a guard answering false → nothing changes |
| Red button, no project | `main` open, `session.current == null` | guards pass → Projects opens → `main` destroyed | — |
| Open from Projects | Projects open, no `main`; a project opens | `main` opens, then Projects is destroyed — unless the outcome carries warnings: then Projects stays open with its notice and is activated once `main` is up (Claude's proposal; I7) | — |
| Switch from Projects | Projects beside `main`; another project opens | `main` switches in place; Projects closes (no warnings) | — |
| Close Projects | Projects destroyed, no `main` | process exits (even with Settings open) | — |
| Close a non-lifeline dialog | Settings/Configurations-like window destroyed, `main` or Projects open | no exit | — |
| Same key twice | `openOrActivate('projects', …)` while open | no second window; the open one is activated | `create` on an open key throws `StateError` |
| Dialog minimum | a dialog opened with `minWidth: 680, minHeight: 440` | the controller receives exactly those constraints; the project window receives 880 × 560 | a dialog without constraints does not compile |
| Key status | focus event focused for view A, then B | A's root `inactive` true, B's false; before any focus event every root is active (Claude's proposal); unfocused for the key view → all inactive | — |
| Theme switch | `setThemeMode(dark)` from any window | every open window's root resolves night; native appearance set on every app window | — |
| Dock reopen | native `reopen` (no visible window) | `main` open → unminimised + activated; else Projects opened or activated | — |
| Quit | ⌘Q (`onExitRequested`) | close guards first; false → `AppExitResponse.cancel`, worker untouched; true → worker closes, exit | — |
| Content-sized frame | position-only window, saved frame | origin restored by its saved top edge; a later content height change keeps the top edge | no saved frame → centred over `main` (else the screen) once its content size is known, before it shows |

## Design Notes

**Native** (Claude's proposals marked in code). `restore` parses `chrome` (`main`|`secondary`), `frame` (`full`|`position`) and `level` (`normal`|`floating`) strictly. Order: chrome (kind) → `isRestorable = false` → frame → observers. `secondary` keeps the engine's mask and inserts `.fullSizeContentView`, then everything `main` does except the mask, the minimum and the `CanvasBase` background — its background is the new `WindowFillBase` set (`--fl-bg-solid`: paper `#FFFDFA` any, night `#1A1F35` dark). Frame `full` restores/saves as today. Frame `position`: saves the frame as today; restores only the origin, so that the saved **top edge** (`origin.y + height`) stays: `y = savedTop − current height`; afterwards each `didResize` re-anchors to the last known top (updated on `didMove`), so a content height change keeps the top edge (I1; if this flickers, the fallback is a fixed height per tab, ledger). First placement without a saved frame: `main` uses `placeForFirstLaunch`; a dialog is centred over the visible `main` window (else the screen's visible frame), clamped into the visible frame — a sized dialog at `restore`, a content-sized one on its first resize before it shows (its frame is meaningless earlier), with `didBecomeKey` as the fallback. `level: floating` sets `.floating` while `NSApp.isActive` and `.normal` on resign (the splash's observers, per window). A `#if DEBUG` `NSLog("zanshin.window <key>: styleMask … collection … restorable … level …")` after `restore` and on level changes is the probe's readout of what CGWindowList cannot see. `applicationShouldHandleReopen` with no visible window → `WindowingBootstrap.reopen()` → `invokeMethod("reopen")` on `zanshin/window_frames`.

**Dart API shape** (Claude's proposal; adapt names if the code reads better): `create`/`openOrActivate` keep `size`/`constraints` for project windows and take an optional `DialogWindowSpec dialog` that switches to a dialog window; `AppWindows.setCloseHandler(key, Future<void> Function()? handler)`; `addCloseGuard(Future<bool> Function())`. The coordinator never acts before `onShown` (the first window must exist before a second `main` could be created); its first-window decision checks `Directory(openProject).existsSync()`.

**Projects keeps its report** (I7, Claude's proposal until 10.23's toast): an open whose outcome carries warnings leaves Projects open with its notice and activates it after the project window is up; without warnings Projects closes.
