# Epic 11 Context: Floating app shell (Flutter UI)

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Build the macOS app around the commit graph: one project window in which the graph fills the space and every control floats above it on glass islands. A user picks or adds a project, organises projects in groups, switches projects from the capsule, changes settings in one window, fetches and pushes from the top bar, and steps back through the operation log. The epic owns everything that is not graph-semantic — the design-system foundation, glass materials and Zs control library (package `zanshin_ui`, with the Widgetbook catalogue and Marionette setup), the overlay host, native chrome and window foundation, projects and the Projects window, Settings, the menu bar (with native checkmark and greying state), sync, the Undo Timeline, retiring the old docked mock UI, and making the English UI l10n-ready (strings in ARB files). Claude builds it and Ralph reviews every story; Epic 10 plugs its graph-semantic parts (search, View capsule, inspector, minimap, @ pill, toast, Configurations) into this epic's slots.

## Requirements & Constraints

- **Design input.** The design system in `_bmad-output/implementation-artifacts/design_system/` is the reference (synced through #15; `dsSyncedThrough` is 15 since 11.15). Precedence: decisions recorded in epics.md > DS tokens and CSS > DS prose and cards > the clickable prototype in `design/`. The design is inspiration: small gaps get a marked "Claude's proposal". Where the design does not fit jj, that is expected, not a defect — the owning story builds it along jj's behaviour. A DS change to a token or icon turns the DS parity test red until the token layer follows.
- **Done** = `cargo make test` passes and Claude has checked the change visually: open the affected use cases in the catalogue (or the app) via Marionette's `zanshinCatalogue.open`, screenshot, compare with the DS cards rendered full size. Hover-only surfaces need a use case showing them open. No golden tests; app tests use fake ports and never call jj config verbs for real; Dart lines are not coverage-measured, so the named witnesses are the safety net. Native chrome is checked only by the CGWindowList probe.
- **CLI parity.** The UI never composes jj operations; it pre-fills parameters from the effective config and passes them explicitly. Every jj command shown exists in v0.46.0 exactly as written, in full, shell-quoted, with the change id. Refusals and hints are verbatim. Say "bookmark", never "branch"; "stale" means only the working copy.
- **Accessibility.** VoiceOver semantics on every surface (macOS reads roles from semantics flags only) and a keyboard path; focus rings only for keyboard focus (`zsRingFollowsInput`: a pointer press hides them, a navigating key shows them — Flutter alone counts a mouse as keyboard).
- **System settings apply live, with no in-app switch.** Reduce motion by property (movement, size, rotation, stroke drawing → 0; fades keep durations; the spinner turns). Reduce transparency or increased contrast paints glass solid. An inactive window paints no hover or focus ring and neutralises the accent except its live copies (progress, flash, drop targets, links).
- **Undo** lives in three places: ⌘Z (only Zanshin's own latest operation while current), the toast, the Undo Timeline. Every undo ends in the toast "Undid ‹action› · Redo". List edits in the Projects window have no undo.
- **English, l10n-ready.** The app stays English only (no second language, no language setting), but user-facing strings (labels, tooltips, captions, menus, dialogs, VoiceOver labels) go through ARB files via `gen-l10n`, with key, description and ICU plurals/placeholders; no hard-coded UI text, guarded by `app/test/l10n/hard_coded_strings_test.dart` (widgetbook and tests exempt). The app's strings are `app/lib/l10n/app_en.arb` (`context.l10n`, `platformStrings()` without a context), `zanshin_ui`'s `packages/zanshin_ui/lib/l10n/zs_en.arb`; after an edit run `flutter gen-l10n` in that package and commit the generated files. Window roots register `zanshinLocalizationsDelegates`. jj's own words shown verbatim (commands, jj's errors and hints) and the product name stay out of the ARB, marked `// l10n-ignore: <reason>`. Dates keep per-locale `intl` formatting (`ensureDateFormatting()` before a `DateFormat`).
- **Stale working copy** is a project-level state without Retry; Fetch, Push, Change items and the op log are disabled with "Working copy is stale".

## Technical Decisions

- **Code locations.** `packages/zanshin_ui/lib/src/` holds `design/` (tokens), `materials/`, `icons/`, `controls/`; tests mirror under its `test/`. The app imports only `package:zanshin_ui/zanshin_ui.dart`; the package never depends on `zanshin_core`, `inject_*`, `marionette_flutter` or the app. App features: `app/lib/src/features/{shell (host, menu bar), projects, settings, sync, undo_timeline, window}/`, tests mirrored under `app/test/`. The catalogue (`app/widgetbook/`) and the shared Marionette configuration stay in the app. The gate is change-aware: a test reading a file outside its package needs that path in the gate-plan rules.
- **Bridge.** The app imports only `package:zanshin_core/zanshin_core.dart`; each `[UI/bridge]` story adds its types to the `show` list.
- **No Material or Yaru look.** Every control is a Zs control on the shared state core; text entry is an undecorated `TextField`. `MaterialApp`/`ThemeData` come only from `package:material_ui` (its `ThemeMode` is not Flutter's). Designed visuals are a `RenderBox` with text slots, not `Column`/`Row` trees. A new shared visual is built in `zanshin_ui` by its first user (e.g. 11.15's `ZsDragGhost`, kinds `project`/`group`).
- **Tokens and accent.** `Zs*` `ThemeExtension`s over theme (night/paper) × accent family, with contrast/inactive/transparency/motion deltas; `of(context)` falls back to night. The accent role (`--accent*`, `--focus-ring`) marks selection, focus, controls, menu highlights, drop targets and the flash; it follows the macOS accent unless Settings says "Zanshin", moon only under Multicolor ("moon" in older story text means this role). Gold stays with @ and the one primary action; data colours stay fixed. Selected data row `--accent-soft`, navigation `--fl-on`.
- **Icons and fonts** are `zanshin_ui` assets; SVGs are precompiled and loaded by the boot-time `IconRegistry` (tests load it in `setUpAll`/`tester.runAsync`).
- **Materials.** One `BackdropGroup` per window; one menu material for menus, popovers, callouts. Only two sheets, ConfirmDialog and Push, Flutter-drawn; a scrim click does nothing. Separate windows get an opaque fill.
- **Windows.** Settings, Projects and jj log Configurations are parentless dialog windows, one per key, via `AppWindows.openOrActivate`, each with its own minimum. One project window (one frame key) that switches projects in place. The app quits only when Projects closes with no project open. Every window sets `isRestorable = false`; each root is `ZanshinWindowRoot` with a key (Marionette `ancestor_keys`). Window content stays window-agnostic; each window story adds a Widgetbook "Windows" use case opening the real window.
- **Geometry.** Traffic lights are measured, never moved: the bar centres on the block, the first island at block end + 12, content top 60 (68 full screen). Project-window minimum 880 × 560; the graph keeps ≥ 320 px. Inspector 380–720 (460), left panels 240–440 (300); the remembered width persists (AppSettings `layout`), never the effective one; when space runs out the inspector shrinks, then the panel, then the pinned panel collapses keeping its pin.
- **Calm scrolling** is owned by 11.3's `CalmController`; the shell counts wheel and trackpad, the graph reports its canvas pans and fling glides through `ShellScope.maybeOf(context)?.reportUserScroll` and never a programmatic scroll. The graph takes `ShellScope.insetsOf(context)` as its viewport insets unchanged.
- **Preferences and registry** are defaulted fields in `packages/zanshin_settings`, no migration; the project registry is `AppSettings.projects`, edited through `ProjectRegistry`.
- **Settings writes** (11.7) go to the tab's scope through the config verbs; the Immutable commits page writes `revset-aliases."immutable_heads()"` at repo scope (bookmarks as `present(<name>)`, a custom revset only once `revsetCounts` resolves it, Reset = `configUnset`), reads the effective alias back onto its controls, and each write re-requests the graph layout once.
- **Menu bar.** Built in Dart: one `PlatformMenuBar` above the `WindowManager`, labels from `app_en.arb`, over `AppMenuModel`, which follows the key window, the session, the open sheets, the focused text field and the project window's graph binding; the system items are `PlatformProvidedMenuItem`s the engine copies from `MainMenu.xib` by selector (so those xib items stay, with their English titles). Key equivalents reach Flutter first, so no Dart key handler duplicates a menu shortcut. Two engine limits remain: `PlatformMenuItem` has no checked state, and `PlatformProvidedMenuItem.enabled` is ignored natively; the engine also never sets `NSApp.windowsMenu`. 11.17 closes them with a runner-side method channel that sets `state` and `enabled` on named `NSMenuItem`s of `NSApp.mainMenu` (found by a stable identifier the Dart menu assigns) and sets `windowsMenu` to the Window menu if unset — no engine fork, no items beyond 11.13's.
- **Tooling.** Widgetbook 3.25.0 pinned exactly (no 4.x). `marionette_flutter` ^0.7.0, one shared configuration; match by `Semantics(identifier:)` or text, never coordinates. `@experimental`/`@Deprecated` APIs only with an explicit `// ignore:` plus `// WHY:`; `dart analyze --fatal-infos --fatal-warnings` stays clean.

## UX & Interaction Patterns

- **Top bar** Place · View · Action; the centre gives way first when narrowing.
- **Rail:** Bookmarks and Undo Timeline only (Workstreams and Reviews dropped). Previews are hover-only; the keyboard path is the rail button (↩ pins).
- **Calm scrolling:** user scrolling moves the chrome aside, gated by "Hide controls", back after one 650 ms wait; only this window's menus, popovers and sheets block it.
- Transient surfaces share one exit (fade + mirrored drift × motion). **Esc** closes the topmost surface, in its own window only.
- **Shortcuts:** ⌘, opens Settings on the last tab, never toggles. ⌘W on the project window closes the project and shows Projects. ⌘J/⇧⌘J only scroll. View › Reload ⌘R = 10.12's reload button (graph and project reading, coalesced). Fetch has no shortcut; Push… is ⇧⌘P. Text shortcuts win inside fields. Project commands reach the project window from any Zanshin window.
- **Change menu** acts on the selection, else @, and names its target ("Abandon @"); it includes Revert (no shortcut, greyed while the target is @).
- **Settings pages:** a navigation row opens a page that replaces the tab's groups; "‹ <project>" and ⌘[ go back; the window title is the page name.
- **Projects tree (11.15):** Finder-like — a click on empty space deselects; rename keeps on ↩ or click elsewhere, a new group cancels on click elsewhere; Delete group keeps its contents and, like Remove from list, asks first (neither has an undo); an empty group opens like any other; the search is not focused on open; Move to group › ends with "New group…"; drag carries a ghost naming the destination ("Into <group>" / "To the top level").
- **Text:** menu bar Title Case, everything else sentence case, English. **Cursor:** arrow, except I-beam on text entry, `progress` while busy, `grabbing` on a held canvas, resize cursors on edges. **Change ids:** bold shortest unique prefix, no gap.
