## Intent

**Problem:** Zanshin reads a handful of named config values and rewrites the repo-level file privately for two remote verbs and the `trunk()` alias, but it has no general config surface. A user cannot see where a value comes from, cannot set `user.name`/`user.email` (Story 9.27's `identity_missing` prompt has no target), cannot change `revsets.log` (Story 9.25) or `snapshot.auto-track` without leaving the app. SourceTree-style repository and global settings need exactly the verbs `jj config` offers, at the CLI's scopes, with the CLI's file-selection and refusal rules — so that a value set in Zanshin is the value the CLI reads next, and vice versa.

**Approach:** Port the `jj config` group @ v0.44.0 (`cli/src/commands/config/{list,get,path,set,unset,edit}.rs`) as typed reads and writes over the effective stack Story 9.27 opens the repo with, for all three CLI scopes (`--user`, `--repo`, `--workspace`). `edit` becomes a validated raw-file round trip because the GUI replaces `$EDITOR`. One `ConfigFile` writer family serves the new verbs and the existing private writers.

## Boundaries & Constraints

**Always:**
- **`list`**: port `resolved_config_values` (`cli/src/config.rs:148` ff.) → rows `{ name (dotted), value (TOML text, whitespace-trimmed), source (Default | System | EnvBase | User | Repo | Workspace | EnvOverrides), path?, overridden }`; filters exactly as `cmd_config_list`: optional name prefix, scope (keep `source == scope`), `include_defaults` (only without a scope), `include_overridden`. An empty result is a result, not an error — the CLI's "No config to list." / "No matching config key" are stderr notes.
- **`get NAME`**: `settings.get_value(name)`; a string comes back unquoted, every other type in TOML syntax (`cmd_config_get`). `NotFound` and a table at the path → typed refusals.
- **`path SCOPE`**: user → every candidate path in the CLI's order, existing or not (`user_config_paths()`); repo / workspace → the secure path, CREATING the config directory and id file when missing — the CLI's documented side effect (`config path --repo`), which `config.rs::new_repo_config_file` already implements; add the workspace twin. No determinable path → typed refusal (`No user config path found` etc.).
- **`set SCOPE NAME VALUE [path]`**: the file is chosen as `edit_config_file` does (`config/mod.rs`): the existing layers of that scope, else a new file at the CLI's default (`config_files_for` `:693-708`; user → the first candidate of `user_config_paths()`; repo / workspace → the secure file). More than one existing file → the CLI prompts; Zanshin returns the candidates as a typed refusal and accepts an explicit `path` that must be one of them (FR-JJ-17). `VALUE` is parsed with `parse_value_or_bare_string` (`:64-79`: TOML expression, bare-string fallback). `ConfigFile::set_value` errors (`WouldOverwriteValue`, `WouldOverwriteTable`, `lib/src/config.rs:102-122`) → typed refusals, nothing written. Setting `user.name` / `user.email`: the CLI's `check_wc_author` → fact `working_copy_author { name, email }` when `@`'s author differs from the new value (the "only impacts future commits … use `jj metaedit --update-author`" warning). Save = `ConfigFile::save` — `toml_edit` round trip, comments and formatting preserved.
- **`unset SCOPE NAME [path]`**: same file selection; `delete_value`; `None` → refusal `"<name>" doesn't exist`; `WouldDeleteTable` → refusal.
- **`edit SCOPE [path]`** → two GUI halves: `config_file_read(scope, path?)` returns `{ path, text }`, creating an empty file when absent (the CLI saves before opening the editor); `config_file_write(path, text)` validates the text as a `ConfigLayer` of that source BEFORE writing and refuses with jj-lib's parse error (message + span) otherwise — the CLI's re-edit loop, with the UI holding the buffer. Writes only to a path `path SCOPE` would return.
- **After every write** the Story 9.27 reload runs, so the next verb sees the new settings; **no operation is written** — config files are not repo state (`jj config set` writes no op).
- **One writer family.** `remove_remote_from_repo_config`, `rename_remote_in_repo_config`, `set_trunk_alias` and Story 9.25's `revsets.log` writer move onto the same `ConfigFile` helpers and the same file-selection rule.
- Surface: `.fbs` request/response tables; extern fns `zanshin_config_list` / `_get` / `_path` / `_set` / `_unset` / `_file_read` / `_file_write`; `WorkerCommand`s; `docs/ffi-abi.md` + `docs/rust-error-codes.md` rows; coverage ratchet; MCP optional (Epic 7).

**Ask First:**
- Error-code granularity: separate codes (`jj.config_not_found`, `jj.config_type`, `jj.config_would_overwrite`, `jj.config_ambiguous_file`, `jj.config_parse_error`) vs. `jj.config_error` with a `kind` in `context`.
- Whether `config gc` (the group's seventh verb: prunes stale secure config dirs) rides along or gets its own line.
- Whether `set` additionally accepts a pre-typed value from the UI (string / bool / integer) besides the TOML text.

**Never:**
- No catalogue of "known" keys, no key validation, no schema: the CLI sets any key (Story 9.25's revset completion is the one deliberate exception, for revsets only).
- No `.gitconfig` reading or writing, no `$EDITOR`, no operation-log entry for config writes.
- No lowering of `coverage-baseline.txt`, no `exclude_prefix`.

**Acceptance Criteria:**
- Given a value set through Zanshin at any scope, when the same key is read through `jj config get`/`list` on the same repo, then value, file and source match; and the reverse for a value set through the CLI.
- Given two existing user config files, when `set` is called without `path`, then nothing is written and the refusal names both files; with one of them as `path`, the write lands there only.
- Given `user.email` is set while `@` was authored by another identity, then the write succeeds and the result carries the working-copy author fact.
- Given invalid TOML text, when `config_file_write` is called, then the file is unchanged and the refusal carries jj-lib's parse error and span.
- Given every write, then `jj op log` is unchanged and the next Zanshin verb runs on the new settings.
- Given a repo whose stack makes `Repo::open` refuse (wrong-typed `git.*` key) or a broken user TOML, when the config verbs are called with the workspace root (no handle), then they behave as the CLI's config commands do in that state (Design Notes § Broken stack) and `config_file_read`/`config_file_write` repair it.
- Given `cargo make test`, then every step except the 3 pre-existing `test-flutter` splash-card failures is green, including the coverage ratchet and the extern-fn guard for all nine new externs.

- `file_read` of an absent file (matrix: "empty file created; `{ path, "" }`"): the CLI's `jj config edit` creates it with `ConfigFile::load_or_empty(..).save()`, which writes jj-lib's `#:schema https://docs.jj-vcs.dev/latest/config-schema.json\n\n` prefix. On-disk parity wins: the created file and the returned `text` are that prefix (an empty config document), not a zero-byte file.
- The contract's "Story 9.25's `revsets.log` writer" does not exist (9.25 has not landed; `revsets.log` is only read, `config.rs:841`), so the writer family is the three existing writers.
- `EnvBase`/`EnvOverrides` rows carry `path = None`; Zanshin has no `CommandArg` layer, so `ConfigValueSource` has no such member.

**API** (`crates/zanshin-jj/src/config_cmd.rs`, all free functions — no `Repo` handle, see § Broken stack; `workspace_root: Option<&Path>` is the CLI's `-R`: `None` = run outside any workspace):
- `ConfigScope { User, Repo, Workspace }`; `ConfigValueSource { Default, System, EnvBase, User, Repo, Workspace, EnvOverrides }`; `ConfigEntry { name: String /* dotted */, value: String /* TOML, trimmed */, source, path: Option<PathBuf>, overridden: bool }`; `ConfigListQuery { name: Option<String>, scope: Option<ConfigScope>, include_defaults: bool, include_overridden: bool }`.
- `config_list(root, &query) -> Result<Vec<ConfigEntry>, ConfigCmdError>`; `config_get(root, name) -> Result<String, _>`; `config_path(root, scope) -> Result<Vec<PathBuf>, _>`.
- `config_set(root, scope, name, value_text, path: Option<&Path>) -> ConfigSetOutcome { result: Result<ConfigSetResult { path, working_copy_author: Option<WorkingCopyAuthor { name, email }> }, ConfigCmdError>, precondition: Option<Precondition> }` — `precondition` is `Some` iff `check_wc_author` ran the snapshot (success or partial), on the Ok AND the Err path (9.26 rule: the precondition rides every envelope whose verb ran it).
- `config_unset(root, scope, name, path) -> Result<PathBuf, _>`; `config_file_read(root, scope, path) -> Result<ConfigFileText { path, text }, _>`; `config_file_write(root, path, text) -> Result<(), _>`; `config_gc_list() -> Result<Vec<MissingRepoConfig { config_dir, repo_path }>, _>`; `config_gc_delete(&[PathBuf]) -> Result<ConfigGcResult { deleted: Vec<PathBuf>, failed: Vec<ConfigGcFailure { config_dir, reason }> }, _>`.

**Per-verb semantics (the CLI's, step for step):**
1. **Workspace root** (`-R` parity): `Some(p)` → canonicalize (fail → `PathNotFound`), `DefaultWorkspaceLoaderFactory.create` (fail → `NotARepo`); `loader.repo_path()` is the repo dir (secondary workspaces follow `.jj/repo`), `workspace_root/.jj` the workspace dir.
2. **Startup stack** (every verb except `config_file_read`/`config_file_write`): load the raw stack (System → EnvBase → User → [Repo → Workspace] → EnvOverrides, the existing side-effect-free read path), resolve with the verb's command name, `UserSettings::from_config` — any fault → `ConfigCmdError::Config` naming path/key (`jj.config_error`), BEFORE any disk effect. `ui.*` startup reads are terminal UX and not replicated.
3. **File selection** (`set`/`unset`/`file_read`; CLI `edit_config_file`): User → the existing user files (the raw User layers; `file_read` enumerates the same files WITHOUT parsing) else the first `user_config_paths` candidate (parent `create_dir_all` 0700, errors ignored); none → `NoConfigPath`. Repo/Workspace → the create-forcing secure resolver (`SecureConfig::load_config`: creates `<config>/jj/{repos|workspaces}/<id>/` + `metadata.binpb` + the id file when missing, migrates a legacy file — exactly what the CLI's startup `maybe_load_config` + force yields); no workspace or no config dir → `NoConfigPath`. >1 candidate and no `path` → `AmbiguousFile { candidates }`; an explicit `path` not among the candidates → `AmbiguousFile { candidates }`; nothing written in either case. The chosen file is loaded with `ConfigFile::load_or_empty(source, path)` (parse error → `jj.config_error`).
4. **`set`**: parse name (`ConfigNamePathBuf`; invalid → `Parse`) and value (`parse_value_or_bare_string`; error → `Parse`) → file selection → if name is exactly `user.name`/`user.email` and a workspace root was given: `Repo::open` (any failure → skip silently) → `repo.snapshot()` (the CLI's `workspace_helper` snapshot incl. colocated import; failure → skip silently, partial report kept) → `@`'s author; fact iff `value.as_str() != Some(orig_field)`; the fact carries BOTH current fields → `ConfigFile::set_value` (`WouldOverwriteValue|WouldOverwriteTable` → `WouldOverwrite`, nothing saved) → `save` (fail → `jj.config_error`).
5. **`unset`**: parse name → file selection → `delete_value` (`WouldDeleteTable` → `WouldDeleteTable`; `Ok(None)` → `NotFound` with the CLI text `"<name>" doesn't exist`) → `save`. (CLI parity: a repo/workspace unset with no file still creates the secure dir, then refuses.)
6. **`path`**: User → every candidate in order, existing or not, creates nothing; Repo/Workspace → the create-forcing secure path (dir + metadata + id file; NOT `config.toml`); none → `NoConfigPath`.
7. **`file_read`** (`jj config edit`, editor half 1): file selection WITHOUT the startup stack; if the file does not exist, `save()` an empty `load_or_empty` document (schema header) first; return the exact bytes as UTF-8 text (non-UTF-8 → `jj.config_error`).
8. **`file_write`** (editor half 2): `path` must be one of the files `file_read` can currently return for SOME scope of this root (user files + default candidate, repo/workspace secure file resolved side-effect-free) → else `AmbiguousFile` with that set; its scope gives the `ConfigSource`; validate `ConfigLayer::parse(source, text)` BEFORE writing (error → `Parse { message, span }`, file untouched) → `fs::write`.
9. **`gc_list`/`gc_delete`**: startup stack without workspace; root = `<config>/jj/repos` (no config dir → `NoConfigPath` "No config directory found"); `find_missing_repo_configs` ported verbatim; `gc_delete` re-runs it and deletes only requested dirs that are still in the missing set (others → `failed` with reason "not a missing repo config directory"), `remove_repo_config_dir` failures → `failed` with the io error text; order of `deleted` = the sorted missing order.
10. **No operation** is written by any config verb itself (only `set`'s snapshot may, as in the CLI). An open `Repo` handle re-derives its settings on its next verb through 9.27's fingerprint (`refresh_settings`), which every config write changes — no extra hook.

**Broken stack (9.27 carry-over).** The CLI's config verbs never load the workspace, so a wrong-typed key only jj-lib's workspace load reads (`git.*`, `working-copy.*`, …) does not block them — and it does not block Zanshin's either, because they take a workspace root instead of a `Repo` handle (the root cause of the deferral). A TOML parse error in any layer, or a wrong-typed startup key (`user.*`, `operation.*`, `signing.*`, `debug.*`), fails every CLI `jj config` verb at start-up: Zanshin's `list`/`get`/`path`/`set`/`unset`/`gc_*` refuse identically (`jj.config_error`, path or key in `context`). `config_file_read`/`config_file_write` are the GUI's stand-in for the user's own editor — the CLI's repair path is opening the file its error hint names ("Check the config file: <path>") in any editor, which no jj start-up check gates — so they skip the startup stack and touch only the one file (and, for repo/workspace, the same secure resolution `path` uses). This closes `deferred-work.md:366`.

**Error codes** (`ConfigCmdError` → FFI):
- `Config { reason }` → `jj.config_error` (existing): stack load/resolve/settings faults, unreadable/unparseable selected file, bad `config-id`, secure-config/metadata errors, save/`fs::write` failures, gc root read failures ("Failed to check/read <root>").
- `PathNotFound { path }` → `jj.path_not_found`, `NotARepo { path }` → `jj.repo_not_found` (existing, `-R` parity).
- `NotFound { name }` → NEW `jj.config_not_found` (get "Value not found for <name>", unset `"<name>" doesn't exist`).
- `WouldOverwrite { reason }` → NEW `jj.config_would_overwrite` (set: `WouldOverwriteValue`/`WouldOverwriteTable`, jj-lib message in `context`).
- `WouldDeleteTable { reason }` → NEW `jj.config_would_delete_table` (unset: `WouldDeleteTable`; different remedy — unset the leaves or edit the file).
- `AmbiguousFile { candidates }` → NEW `jj.config_ambiguous_file` (`context` = candidate paths, one per line).
- `Parse { message, span }` → NEW `jj.config_parse_error` (`set` name/value TOML, `list` prefix, `file_write` text; `context` = `"<start>..<end>\n<message>"` when jj-lib/toml_edit reports a span, else `<message>`).
- `NoConfigPath { reason }` → NEW `jj.config_path_not_found` (CLI texts: "No user/repo/workspace config path found[ to edit]", "No config directory found").
- FFI-only: a request missing a required field, `ConfigScope::Unspecified` where a scope is required, or `list` with a scope AND `include_defaults` (clap conflict) → `jj.invalid_input` (existing).

**FFI shape.** A new two-parameter shape `(const uint8_t *data, uintptr_t len)`: every input — including `workspace_root` (absent = no workspace) — lives in the request table; the ladder is null data → `ffi.null_pointer`, unverifiable buffer / wrong `kind` → `ffi.invalid_argument`, missing required field → `jj.invalid_input`, then the verb's codes (no handle rung). Handle-less on purpose (§ Broken stack); the Dart side adds `ZanshinWorker` methods only (no `RepoHandle` sugar — UI is Ralph's). `file_write` success is `ok_empty()`.

**Coverage & tests.** `config.rs` stays at 100%, new `config_cmd.rs`/ffi `config.rs` ≥ 80%: keep the ports and selection logic in pure functions over `ConfigEnv`/explicit paths, unit-tested inline. User-scope rows only in the single-`#[test]` `JJ_CONFIG` binary. No test may read or write the developer's real `~/.config/jj`: every Rust binary that calls a repo/workspace/gc verb pins `XDG_CONFIG_HOME` to a leaked temp dir; Dart via the `Makefile.toml` pin.
