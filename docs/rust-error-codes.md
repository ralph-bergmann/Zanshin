# Rust Error Code Registry

AR-P-4 canonical registry for all `error.code` strings emitted across the Zanshin Rust workspace.

---

## Convention

Error codes follow the dotted `<domain>.<reason>` format, e.g. `jj.repo_not_found`.

**Rules:**

- **The CLI's hint lines go in `hints`, never in `context` (Story 9.56).** `FfiError.hints` carries a refusal's `Hint:` lines verbatim, in the CLI's order; absent = none. The codes that carry hints say so in their row below.
- **User data goes in `context`, never in `code`.** The `code` is a stable machine-readable key; human-readable detail (paths, messages) belongs in the `FfiError.context` field.
- **Reasons never change after release.** Once a code ships in a released version, its string is frozen. Add new codes rather than renaming existing ones.
- **All codes are emitted from `crates/zanshin-ffi/src/envelope.rs`.** Domain crates (`zanshin-jj`, etc.) translate their errors into `FfiErrorObj`; `envelope.rs` serialises them. No `error.code` string may appear outside `envelope.rs` (AR-P-4, `architecture.md:641`).

---

## Domain List

| Domain     | Crate / subsystem                  |
|------------|------------------------------------|
| `internal` | `zanshin-ffi` — infrastructure-level panics and serialisation failures |
| `ffi`      | `zanshin-ffi` — FFI contract violations (null pointers, invalid handles, UTF-8) |
| `jj`       | `zanshin-jj` — jj-lib operation errors |
| `diff`     | `zanshin-diff` — diff computation errors |
| `graph`    | the graph topology call (`zanshin-ffi`'s `graph.rs`, `zanshin_graph_topology`) *(2026-10-01, Story 4.12: until then `zanshin-graph` — DAG lane-assignment errors; that crate was removed)* |
| `watcher`  | `zanshin-ffi` watcher subsystem — filesystem-watch errors |
| `mcp`      | `zanshin-mcp` — MCP server errors |
| `env`      | `zanshin_core`'s login-shell reader — the app's start-up environment (Story 9.36; a warning code only, built in Dart) |

## Warning Codes

Story 9.32: the codes `Envelope.warnings` carries — the jj CLI @ v0.44.0's `ui.warning_*` blocks
on the paths Zanshin ports, as `{ code, message }` facts. A warning never changes a call's outcome:
it rides the ok envelope AND the error envelope (a precondition that warned before the verb
refused), and is ABSENT on the wire when there is nothing to say (read as an empty list; never on
`PANIC_FALLBACK_ENVELOPE`). The same single-emission-point rule as the error codes applies: every
string below is a `pub const` in `crates/zanshin-ffi/src/envelope.rs`, mapped from
`zanshin_jj::WarningKind` by `warning_code()` alone (MCP inherits the Rust `Warning` list). Warning
codes never appear in a `# Errors` rustdoc section. The one exception to that single-emission
rule is `env.login_shell_unresolved` (Story 9.36): Zanshin-only (no CLI site — a terminal `jj`
simply inherits its shell's environment), BUILT IN DART by `zanshin_core`'s login-shell reader and
never on an envelope, so it has no `envelope.rs` constant and no `WarningKind`.

`message` is the CLI's text for the case, verbatim: English, WITHOUT the `Warning: ` heading and
without the CLI's hints, paths rendered as the CLI renders them from the workspace root. Order is
the CLI's print order — the start-up secure-config fix-up (Story 9.37), config-load warnings, the
pre-verb snapshot and imports, the verb body, then `finish_transaction`. Config-load warnings (alias entries, alias redefinition, `immutable_heads()`
diagnostics) are recorded ONCE per call, as the CLI loads them once per command. Since Story 9.33
the creation symbols (`zanshin_repo_init` / `_clone` / `_convert`, and `zanshin_jj::CreationOutcome`)
carry them too, in their own CLI flow's order: a conversion's refs step comes BEFORE its config
loads (`git/init.rs:251-254`) — see `crates/zanshin-jj/src/convert.rs`'s module doc.

`cu` = `cli/src/cli_util.rs`; every CLI path is relative to `../jj/cli/src/` at tag `v0.44.0`.

### Not ported / out of scope

These CLI warnings have no code, each for the reason given (and the story that owns it, if any):

- **`trunk()` fallback** (cu:545-552) — the resolution fallback itself is not ported; its warnings come with it (deferred, `deferred-work.md`).
- **Secure-config messages** (`secure_config.rs`) and the **deprecated-config** note (cu:4617) — Story 9.37; `default_config_migrations()` was empty at v0.44.0 and holds one rule at v0.46.0 (`fix.tools.<name>.line-range-arg` → `line-range-args`), which only rewrites `fix.tools` — no Zanshin verb reads it, so neither the rule nor its note is ported (deferred, `deferred-work.md`, 2026-10-08).
- **"In template expression" parse diagnostics of the user's own templates** (`templates.*`, printed for `show` / `evolog` / `op log` / `file show` / `config list` — `cli_util.rs:419` / `:1165`, `print_parse_diagnostics`) — Zanshin renders none of these display templates: every result is typed data, so there is nothing to diagnose (`jj.short_prefixes_failed` is the one template-build warning Zanshin keeps for them, because the graph walk builds the same index). The templates the describing verbs and `git push --change` render DO warn, as `jj.template_diagnostic` (Story 9.51).
- **`jj workspace root --name`'s start-up environment** — the CLI's named path goes through `workspace_helper_no_snapshot` (`workspace/root.rs`), which still builds `WorkspaceCommandEnvironment`, so the alias-load warnings fire there; `zanshin_workspace_root` loads no config on either path (the workspace loader and store only), so it carries none of them (only `jj.workspace_path_inaccessible`).
- **`jj log`'s own warnings** (`log.rs:367-394`: unmatched FILESETS paths and the "is being interpreted as a fileset expression" notes) — all about its FILESETS arguments; `zanshin_graph_topology` (Story 4.12; `zanshin_graph_slice` before it) takes no FILESETS argument, so they never arise.
- **Fileset parse diagnostics** — jj-lib emits none (re-checked at v0.46.0: `revset.rs` is jj-lib's only `add_warning` caller).
- **Name-pattern diagnostics** (bookmark / remote patterns) — jj-lib emits none (re-checked at v0.46.0, as above).
- **`In remotes.<r>.*` / `In name pattern` diagnostics** of the remote settings `clone`, the conversion's refs step, `bookmark create` and — since Story 9.30 — `git fetch` and the remote-change poll read (`parse_remote_fetch_*`, `load_git_import_options`, `parse_remote_auto_track_bookmarks_map_for_new_bookmarks`) — unreachable at jj-lib 0.44 and, re-checked, still at 0.46, which emit none. Owner: the next jj-lib pin bump re-checks it (the Story 9.0 / 9.0a pattern).
- **Secure-config migration messages** on a freshly created `.jj/` — unreachable there (Story 9.37).
- **`open`** — not a CLI command; it builds no start-up environment. `zanshin_repo_open` carries neither `precondition` nor `warnings`.
- **cu:2277-2281 unresolved conflicts**, **cu:2437-2442 "workspace no longer exists"** (Zanshin errors after committing instead — a recorded divergence) and **`status`'s conflict lines** — status formatter output, not `ui.warning_*`.
- **Pager / editor / argv / alias-command / `debug` warnings** — terminal UX the GUI replaces.
- **Stale working copy auto-update** — Story 9.23.

## Adding a New Code

1. Choose a `<domain>.<reason>` that is lowercase, dotted, and human-readable.
2. Add a `pub const` for it in `crates/zanshin-ffi/src/envelope.rs` (single-emission-point rule).
3. Add a row to this table with domain, meaning, and the story that introduces it.
4. Update the story file to reference this registry.

A new **warning** code (§ Warning Codes) needs, in one change:

1. A `zanshin_jj::WarningKind` variant whose rustdoc cites the CLI's `ui.warning_*` site @ the pinned tag.
2. A `pub const` in `crates/zanshin-ffi/src/envelope.rs` and its arm in `warning_code()`.
3. Its entry in `envelope.rs`'s literal-table test (`every_warning_kind_has_its_registered_code`).
4. Its arm in `crates/zanshin-jj/tests/it/api_stability.rs`'s exhaustive `WarningKind` pin.
5. A `ZanshinWarningCode` constant (and its place in `ZanshinWarningCode.values`) in `packages/zanshin_core/lib/src/ffi/warning.dart`, plus the string in the Dart pin test (`test/ffi/warning_test.dart`).
6. A row in § Warning Codes (CLI site, emitted by, data).
